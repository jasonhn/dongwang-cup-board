# 内战光荣榜排名标准（现行 v6：联赛积分）

**现行标准**：每人初始 0 分，赢一局 **+50**，输一局 **−40**，按积分降序排名；同分比胜场数；胜、负两列完全相同的人**并列同名次**。

本文给出这条规则的**完整定义、可证明的性质、以及被否方案的反例**。文中所有数值都是在仓库里的 `site/data/league.json` 快照（**2026-11-17：18 场、39 名选手、180 人次出场、人均 4.62 场、场数中位数 3**）上算出来的，复现命令见附录 A；§2 的排序恒等式另外在一张 `w, l ∈ 0..20` 的网格（440 条战绩、193,160 个有序对）上逐条数值验证过，验证脚本也贴在附录 A。

分工：**§1–§3 是标准本身的性质，与打多少场无关，长期有效**；§4 的表是**当前快照的读数**，每 15 分钟采集一次数据就会变，重跑 `scripts/rank_stats.py` 即可刷新，不必怀疑推导。**一场比赛是否计入、谁的胜负算给谁**属于统计口径，见 [`docs/执行标准.md`](执行标准.md)，与本文无关。外部文献来源单独标注，见附录 C。

**先说清这条规则的代价**：它比零参数的净胜场（v3）多了一个自由度——赢与输的加分之比 `50:40`，最简是 `5:4`。§6 会说明这个比值为什么是唯一且必须公示的自由度，以及它被否掉的候选为什么全都更依赖人的判断。**v6 与上一版 v5 只差这一个比值**：规则族、排序键、并列判定全都原样，只是把输一局的代价又调高 5 分。后果是本快照 **21 人名次变化**（榜首不变）、盈亏平衡胜率抬到 `44.4%`、高于这条线的人从 28 人变成 26 人，另有 1 人正好落在线上（`4 胜 5 负 = 0 分`）。这是群规层面的取舍，不是算法缺陷，两端都写在 §11。

## 1. 记号、前提与两个守恒式

| 记号 | 含义 |
|---|---|
| `i` | 一名选手（`account_id` 唯一确定） |
| `w_i` | 在当前时间范围内该选手被统计到的**胜场**数 |
| `l_i` | 负场数 |
| `n_i = w_i + l_i` | 总场数（`n_i ≥ 1`，`n_i = 0` 的人不出现在表里） |
| `p̂_i = w_i / n_i` | 样本胜率，也就是表格里「胜率」那一列显示的数（= 胜场 ÷ 总场数；内战都是组队打的，所以它就是你的联赛胜率） |
| `a`, `b` | 群规的两个数字：赢一局 `+a`，输一局 `−b`。本群取 `a = 50`、`b = 40` |
| `S_i = a·w_i − b·l_i` | **积分**，现行排序量 |
| `≻` | 榜单的排序关系（由 §2.1 定义的严格全序） |

下面所有定理先写成 `(a, b)` 的一般形式，再代入 `(50, 40)`。这样做的目的是：**规则里唯一的人为选择被显式地摆在公式里**，任何群友都能用同一个公式复算。

**前提 P1**：一场比赛被统计到的天辉、夜魇人数相同（内战 5v5，10 个位置全部非匿名）。口径体检会逐场检查这个前提，读数见 §4.1，判定规则见 `docs/执行标准.md`。

**命题 1.1（守恒式）** 若 P1 成立，则每场比赛恰好贡献 `m = 5` 个胜场与 `m = 5` 个负场，对全体求和得

```
Σ_i w_i = Σ_i l_i = m × (场数)        于是       Σ w_i / Σ n_i = ½
```

本快照核验：`Σ 胜 = Σ 负 = 90`，按场数加权的联盟平均胜率 = `0.500000`，且不存在两队人数不等的场次。

**命题 1.2（积分不是零和）** 在 P1 之下

```
Σ_i S_i = a·Σ w_i − b·Σ l_i = (a − b)·Σ w_i
```

代入 `(a,b) = (50,40)` 与本快照：`Σ S = 10 × 90 = 900 > 0`（实测 39 人积分之和正是 **900**，最低 `−230`，最高 `260`）。比值越接近 1，总分越接近 0——`a = b` 时总分恰好为 0（那就是净胜场）。这个「凭空多出来的总分」本身就是比值的函数：v4 是 `20 × 90 = 1800`、v5 是 `15 × 90 = 1350`，v6 又压低一档。

**推论 1.2.1（零点语义，必须向群友讲清）** 积分的零点 `S = 0` **不是**联盟中位水平，而是「初始分」。由命题 3.1（下节）`S = n((a+b)p̂ − b)`，所以

```
S = 0  ⟺  p̂ = b/(a+b) = 40/90 = 4/9 ≈ 44.4%        （联盟中位是 p̂ = 50%）
```

也就是说：**0 分的人比联盟平均水平低**，本快照里积分恰好 0 分的人有 **1** 个（`苏锵锵 4胜5负`，第 27 名，正好踩在 `4/9` 上）。与零参数的净胜场（`ΣD = 0`，`D = 0` 精确等于联盟中位）相比，这是积分制引入比值后付出的第一项语义代价：**榜上的「0 分」不表示中游**。不过这一版把零点往中位挪了一格：v4 在 `37.5%`、v5 在 `41.2%`，v6 抬到 `44.4%`，离联盟中位 `50%` 只剩 5.6 个百分点。语义代价变小，换来的代价见 §11 取舍 1。

## 2. 现行标准 v6 的定义

### 2.1 排序键与并列

排序键是 `(S_i, w_i)` 的字典序降序；后两级（昵称字典序 → `account_id`）只决定显示顺序：

```
i ≻ j  ⟺  S_i > S_j
         或 ( S_i = S_j 且 w_i > w_j )
         或 ( S_i = S_j 且 w_i = w_j 且 昵称字典序 i < j )
         或 ( 上面全相等 且 account_id_i < account_id_j )
```

**命题 2.1（前两级相等 ⇒ 战绩完全相同）** `S_i = S_j` 且 `w_i = w_j` ⟹ `l_i = l_j`（因为 `l_i = (a·w_i − S_i)/b` 由 `S_i, w_i` 唯一决定）。所以后两级**不可能产生名次差异**，战绩完全相同的两人名次必然相同，昵称与 `account_id` 只是稳定排序，不造成「谁压过谁」。

名次数字按竞争排名给出：`名次_i = 1 + 压过 i 的人数`，并列的人共用同一个数字，之后不跳号（`1, 2, 2, 4`）。实现见 §9。

### 2.2 三个等价判别式（不依赖浮点）

**定理 2.2** 对任意两名选手，下面三句话互相等价：

```
(1)  S_i > S_j
(2)  a·(w_i − w_j) > b·(l_i − l_j)      代入 (50,40)：50Δw > 40Δl  ⟺  5Δw > 4Δl
(3)  (a+b)·(w_i − w_j) > b·(n_i − n_j)  代入 (50,40)：90Δw > 40Δn  ⟺  9Δw > 4Δn
```

**证明** `S_i − S_j = aΔw − bΔl` 给出 (1)⟺(2)。又 `Δl = Δn − Δw`，代入得 `S_i − S_j = (a+b)Δw − bΔn`，给出 (1)⟺(3)——本群代入即 `S = 50w − 40l = 90w − 40n`，所以 `S_i > S_j ⟺ 9Δw > 4Δn`。两边都是整数运算，全程不做除法，因此不存在浮点误差让同一个人在两次刷新之间跳名次。∎

数值验证：`w, l ∈ 0..20` 且 `n ≥ 1`，共 **440** 条战绩、**193,160** 个有序对，`5Δw > 4Δl`、`9Δw > 4Δn` 与下面的同分结构 **0 处违反**（附录 A）。

### 2.3 同分的结构与「兑换比」

**定理 2.3（同分 ⟺ 战绩差是固定倍数）** 约分到互质：`gcd(50,40) = 10 ⟹ a:b = 5:4`。则

```
S_i = S_j  ⟺  a·Δw = b·Δl  ⟺  5Δw = 4Δl  ⟺  (Δw, Δl) = (4t, 5t)，t ∈ ℤ \ {0}
```

**证明** `5Δw = 4Δl`，`gcd(5,4) = 1 ⟹ 4 | Δw` 且 `5 | Δl`，记 `Δw = 4t` 则 `Δl = 5t`。∎

三个直接推论，都是这条规则最好用的表述：

1. **兑换比恒定**：同分之下场数差恒为 `Δn = 4t + 5t = 9t`。**「多打 9 场，其中 4 胜 5 负」积分一分不变**（`S(4,5) = 200 − 200 = 0`），无论原来是什么战绩（`7胜0负 = 350` 与 `11胜5负 = 350` 与 `15胜10负 = 350` 同分，每一级都多打 9 场）。这个兑换比不随场数漂移，也不随名次漂移。v4 的兑换比是 `8 场（3 胜 5 负）`、v5 是 `17 场（7 胜 10 负）`，v6 收回到 `9 场（4 胜 5 负）`：输一局更贵，但比值更接近 1，同样的场次差要补回的胜场反而更少。
2. **同分之下，胜场多 ⟺ 场数多 ⟺ 负场多**（`t > 0` 时三者同时成立）。所以第二排序键 `w` **就是**「同分时场数优先」，它奖励的是出勤，而不是别的什么。代数上也可以直接看：`w = (S + b·n)/(a+b) = (S + 40n)/90`，`S` 固定时 `n` 越大 `w` 越大。
3. **同分只可能出现在 `t` 的整数倍上**，因此「谁和谁同分」是可以手算枚举的，见 §4 的同分分组表。**而且要诚实说明**：跨战绩同分要求 `|Δn| = 9|t| ≥ 9`，本季最活跃者有 14 场，所以这一档**这次真的撞上了**——榜面上出现 2 组跨战绩同分（`10 分` 与 `−40 分`，见 §4.3），另外仍有 6 组战绩完全相同的并列（21 人）。v5 的兑换比是 `17 场`，本季最长 14 场，所以那一版这一档一条都没有：把比值调到 `5:4` 之后，同分结构重新变得可见。

### 2.4 齐次性：只有比值有意义

**命题 2.4** 把 `(a,b)` 同乘 `c > 0`，排序结果完全不变（`S` 整体乘 `c`）。数值验证：`c ∈ {1, 2, 10, 100}` 时 440 条战绩的排序序列完全一致；快照上 `+100/−80` 与 `+50/−40` 的名次 **0 人不同**（v5 的 `+100/−70`、v4 的 `+100/−60` 同理）。

**结论：50 和 40 这两个数本身不重要，重要的是比值 `5:4`。** 把它写成「赢一局 +5、输一局 −4」会得到一模一样的榜单，选 50/40 只是为了让分值看起来像一个赛季积分，读起来更直观。顺带一条可复算的小性质：`gcd(50,40) = 10`，所以**每个人的积分都是 10 的倍数**。

## 3. 写成「场数 × 胜率」：盈亏平衡线与激励

**命题 3.1** 记 `p̂ = w/n`，则

```
S = a·w − b·l = (a+b)·w − b·n = n · ( (a+b)·p̂ − b )
代入 (50,40)：   S = n · ( 90·p̂ − 40 )
```

**定义 3.2（盈亏平衡胜率）** 令 `S = 0` 得

```
p* = b / (a+b) = 40 / 90 = 4/9 ≈ 44.44%      对外写作 44.4%
```

于是 `S > 0 ⟺ p̂ > 4/9`，`S < 0 ⟺ p̂ < 4/9`（网格验证：440 条战绩全部满足 `S > 0 ⟺ 9w > 4n`、`S = 0 ⟺ w : l = 4 : 5`）。本快照 **26 人**高于这条线（多打就涨分）、**12 人**低于（多打会掉分）、**1 人**正好为 0 分（`苏锵锵 4胜5负`）。对照上一版：线上是 28 人、线下 11 人、线上外 0 人——把输的代价再调大，**「拉更多人上场」的激励覆盖面又窄了一点**，这是本次改动的代价，见 §11 取舍 1。

**命题 3.3（每局的得失恒定）** 任何战绩下，赢一局 `+a = +50`、输一局 `−b = −40`，与当前积分、名次、场数全都无关：

| 当前战绩 | 当前积分 | 再赢一局 | 再输一局 |
|---|---|---|---|
| 6 胜 1 负（榜首） | 260 | 310 | 220 |
| 3 胜 0 负 | 150 | 200 | 110 |
| 5 胜 4 负 | 90 | 140 | 50 |
| 0 胜 3 负 | −120 | −70 | −160 |

**定理 3.4（期望增益不随场数衰减）** 设某人的真实胜率是 `p`，下一局的期望积分变化是

```
E[ΔS] = p·a − (1−p)·b = (a+b)·p − b        代入 (50,40)： 90p − 40
```

这个式子里**没有 `n`**：一个人打了 3 场还是 30 场，下一局的期望增益都是同一个数。对照被废弃的 v1/v2（§5 定理 5.3），那里的期望增益按 `1/(n+k)²` 衰减，打得多的人每局回报趋近于 0。

几个读数：`p = 44.4% → 0`；`p = 50% → +5`；`p = 60% → +14`；`p = 75% → +27.5`；`p = 100% → +50`。

**推论 3.4.1（对所有人中性别率都是正的）** 在「下一局五五开、不含任何关于他是谁的信息」这个中性假设下，`E[ΔS] = (a − b)/2 = +5`，**人人相同**。也就是说：**排得靠前的人不会因为排得靠前而面临「多打一场可能掉分」**。v1/v2 恰恰有这个问题（§5 定理 5.3），这是积分制相对收缩式最重要的激励差别。比上一版的 `+7.5` 又小一档，但性质没变：只要 `a > b`，中性假设下人人都是正收益。

**定理 3.5（落后多少场能追平）** 若某人真实胜率 `p > p*`，落后前一名 `ΔS` 分，在自己保持胜率、对方不再涨分的静态参照下，需要

```
Δn = ΔS / ( (a+b)p − b ) = ΔS / (90p − 40)   场
```

本快照读数见 §4 最后一张表。`p ≤ p*` 的人按自己的胜率追不上——这正是盈亏平衡线的含义，不是 bug，见 §11 取舍 1。

**命题 3.6（一场全胜不会被误当成刷场次）** `S` 对 `n` 的敏感度是 `(a+b)p̂ − b`，当 `p̂ = 0`（一场没赢）时它等于 `−b = −40`：**没赢过的人多打只会掉分**，所以不存在「靠出勤刷分」的通道。这与被否掉的乘法加权（`p̂ × 场次系数`，见附录 C）正好相反——那一路里 `p̂ = 0` 的人恒得 0 分，多打无感，而新人一律并列垫底。

## 5. 为什么放弃带先验常数的 v1/v2：`(w + k/2)/(n + k)`

v1 取 `k = 2`、v2 取 `k = 6`。这一族公式的唯一作用是「把样本胜率往 50% 拉」，`k` 是先验场数，**必须由人指定**。下面四条都是算出来的，每条都是积分规则不需要面对的麻烦。

**5.1 反超所需的 `k` 没有统一取值，且随场数线性上涨**

设甲 `w₁/n₁`、乙 `w₂/n₂`，甲要压过乙需要

```
(w₁ + k/2)/(n₁ + k) > (w₂ + k/2)/(n₂ + k)
⟺  k > k* = 2(w₂·n₁ − w₁·n₂) / ( 2(w₁ − w₂) + (n₂ − n₁) )
```

```
 6胜1负 压过 3胜0负   → k ≥ 3.0
12胜2负 压过 5胜0负   → k ≥ 4.0
25胜5负 压过 10胜0负  → k ≥ 10.0
30胜6负 压过 15胜0负  → k ≥ 20.0
齐次性：同一组对比放大 1×/2×/4×/10× → k* = 3, 6, 12, 30
```

`k*` 与场数成正比 ⇒ **不存在「配好之后长期有效」的 `k`**。赛季每多打十几场就得重新拍一次参数，而每次拍板的依据都不同——这正是「主观干预」的具体形态。积分规则的判据（定理 2.2 的 `5Δw > 4Δl`，等价于 `9Δw > 4Δn`）在任何场数下是同一条不等式。

**5.2 `k` 越大，同场数的人之间区分度越平**

同场数 `n`、胜率差 `Δp` 的分数差是 `n·Δp/(n+k)`：

```
k =  2 → 20 场 75% 与 60% 的分数差 0.1364
k =  6 → 0.1154
k = 12 → 0.0938
```

要「让多打的排前面」就得加大 `k`，而加大 `k` 会同时抹平同场数的人之间的差距——一个参数同时管两件不该管的事。积分规则里同场数的人分数差是 `(a+b)·Δw = 90Δw`，与 `n` 无关。

**5.3 收缩式里高于平均的人再打一局期望要掉分**

「下一局五五开、不带新信息」时

```
E[Δscore_k] = (n/2 − w) / ( (n + k)(n + k + 1) )
```

```
3胜0负 k=2: −0.0500     3胜0负 k=6: −0.0167
6胜1负 k=2: −0.0278     6胜1负 k=6: −0.0137
5胜4负 k=2: −0.0038     5胜4负 k=6: −0.0021
0胜3负 k=2: +0.0500     0胜3负 k=6: +0.0167
```

符号由「样本胜率与 ½ 的大小」决定 ⇒ **目前排得好的人面临「多打可能掉分」，会催生「保住名次就别打」**。按「保持自己的真实胜率 `p`」算，期望增益是 `k(p − ½)/((n+k)(n+k+1))`，随场数按平方衰减（60% 的人第 1 场值 0.0107，第 20 场只剩 0.00086）——规模上恰好是「打得多回报小」。积分规则两条都没有：推论 3.4.1 里中性假设下人人 `+5`，定理 3.4 里真实增益 `90p − 40` 不含 `n`。

**5.4 收缩式永远把 1 胜 0 负 排在 2 胜 1 负 前面**

交叉相乘之后差值**恒等于 1**，与 `k` 无关。取甲 `1胜0负 (w=1,n=1)`、乙 `2胜1负 (w=2,n=3)`：

```
(1 + k/2)/(1 + k) > (2 + k/2)/(3 + k)
⟺ (1 + k/2)(3 + k) − (2 + k/2)(1 + k) > 0
⟺ (3 + 2.5k + 0.5k²) − (2 + 2.5k + 0.5k²) = 1 > 0     对一切 k
```

所以无论 `k` 多大，`1 胜 0 负` 永远在 `2 胜 1 负` 之前——v2 没能修掉这条。积分规则下是 `50` 分 vs `60` 分，`2 胜 1 负` 在前，不需要任何系数（本快照 `2胜1负` 4 人并列第 10、`1胜0负` 4 人并列第 14）。

**5.5 Wilson 类区间也做不到**（详见 §7）：要翻转「3 局全胜 vs 6 胜 1 负」需要 `z ≥ 1.4548`，而工业界常用取值更低（Reddit 生产代码 `z = 1.2816`），照抄等于没改；并且 `z` 又是一个自由参数。

## 6. 客观性：这条规则唯一的自由度，以及它必须怎么被管

净胜场（v3）是**零参数**的。积分制明确多了一个参数：**赢与输的加分之比**。v4 是 `a:b = 5:3`，v5 是 `a:b = 10:7`，现行 v6 是 `a:b = 5:4`。这里不假装它不存在，而是把它管起来。判据表里的「无可调常数」这一条，v6 依然是**有条件通过**：有 1 个已公示的自由度（比值 `5:4`）。

### 6.1 这个自由度的真实维度是 1，而且是群规不是算法

- 命题 2.4（齐次性）：只有比值 `a:b` 有意义，`50/40` 与 `100/80` 榜单完全相同（实测 0 人不同）。所以自由度是 **1 个有理数**，不是 2 个数。
- 它一次决定全部规则，对所有人一致、不随人/场数/时间变（定理 2.2、3.3）。它不会「给某个人加权重」。
- 它被钉在**两处**：`site/app.js` 的 `POINTS_PER_WIN/POINTS_PER_LOSS`、`tests/test_ranking.py` 的 `test_points_rule_is_the_published_one`。对外的公示口径写在 `README.md`、本文档与 `docs/执行标准.md`；网页上留给群友的是**排序量本身**——看得见的「积分」列，以及表头「胜率」「总 K/D/A」（判据 2 不依赖任何解释文字）。改动必须走 PR，同时改代码 + 测试 + README／本文档／执行标准（流程见 `docs/执行标准.md`）。

### 6.2 比值怎么选出来的：两个阈值都是闭式，不是试出来的

`(a,b)` 决定的全部行为只有两处，且都有闭式：

```
盈亏平衡胜率   p* = b/(a+b)
「多赢的人压过少赢的人」的临界比值  a/b > 3/2   （由 8胜4负 vs 6胜1负：2a > 3b）
```

本群取 `a/b = 50/40 = 1.25`，于是 `p* = 44.4%`；因为 `1.25 < 3/2`，第二条阈值**不成立**，`6胜1负(260)` 排在 `8胜4负(240)` 前面。上一版取 `a/b ≈ 1.4286`，同样小于 `3/2`，这一条的方向没有变；再上一版 v4 取 `5/3 ≈ 1.667 > 3/2`，同一组闭式给出 `p* = 37.5%` 与 `8胜4负(280)` 压过 `6胜1负(270)`——**跨过 `3/2` 这条线发生在 `5:3 → 10:7` 那一步，v6 只是把这条阈值继续留在「少赢但输得少」在前这一侧**（§11 取舍 4）。取 `a = b` 就回到净胜场式的 `p* = 50%`。**选 `5:4` 的理由写在这里，任何人都能复算，而不是「管理员觉得这样顺眼」：** 命题 1.1 保证联盟按场数加权的真实平均胜率恰好是 `50%`，把盈亏平衡线放在 `44.4%` 比放在 `41.2%` 更接近这个均值，等于让「掺水的场次」更贵；代价是 `44.4% ~ 50%` 这一段的人多打不再稳赚，见 §11 取舍 2。

敏感性实测（同一个快照，换比值重排）：

```
+50/−40（p* = 44.4%）：与现行榜不同  0 人，榜首 力量护腕 6胜1负
+100/−80（p* = 44.4%）：与现行榜不同  0 人，榜首 力量护腕 6胜1负      ← 齐次性
+50/−35（p* = 41.2%）：与现行榜不同 21 人，榜首 力量护腕 6胜1负      ← 上一版 v5
+50/−30（p* = 37.5%）：与现行榜不同 33 人，榜首 力量护腕 6胜1负      ← v4
+50/−50（p* = 50.0%）：与现行榜不同 13 人，榜首 力量护腕 6胜1负      ← 等价于净胜场 v3
+50/−20（p* = 28.6%）：与现行榜不同 34 人，榜首 力量护腕 6胜1负
+ 3/− 1（p* = 25.0%）：与现行榜不同 35 人，榜首 力量护腕 6胜1负
```

比值在合理范围内怎么动，**榜首都不变**；变的是中段的次序。这就是「一个公示的比值」与「一堆随手调的权重」的区别。

**v3（净胜场）是零参数的，为什么还要换？** 诚实回答：v3 的盈亏平衡线是 `50%`（`D = n(2p̂ − 1)`），落在 `44.4% ≤ p̂ < 50%` 的人多打**完全没有回报**，而这批人在一个混排的内战联盟里是多数——与「拉更多人上场」这个目标冲突。积分制把线降到 `44.4%`（v5 是 `41.2%`、v4 更低 `37.5%`），代价是引入一个必须公示的比值。**这是规则层面的选择（赛事规则），不是算法缺陷**；如果群里更看重「零参数」，退回 v3 是一行改动（把 `POINTS_PER_LOSS` 改成 `POINTS_PER_WIN`，等价于净胜场的排序，见 §11 取舍 2、4）。

**v5 → v6 呢？** 同一族规则里把输的代价再调大：线上人数从 28 人减到 26 人（另有 1 人正好踩在线上），出勤激励覆盖面又窄一格；换来的是质量权重上升（`3胜1负` 从第 6 升到第 5、`6胜5负` 从第 5 掉到第 6）、零点从 `41.2%` 向联盟中位 `50%` 靠了一格、兑换比从 17 场缩到 9 场（于是本季重新出现 2 档跨战绩同分）。本快照 21 人名次变化，榜首不变。两个方向都不涉及算法，取值本身仍是那个已公示的比值。

**明确不接受的三种主观干预**（无论用哪一版公式）：

1. **参数随人/随场数变**（v1/v2 的 `k*` 就是这类）；
2. **临时改数**：任何比值的调整必须走 PR + 测试 + README／本文档／执行标准 同一批提交，不允许「这周先按 40:30 算」；
3. **手工加减某个人的分**：口径层面的处理一律走 `docs/执行标准.md` 的留痕机制（`manual_override_match_ids` 当前为空），而不是改排名公式。

## 7. 被否掉的候选方案

**Wilson 得分下界**（App Store / Reddit 评分排序那一路）

```
LCL(w, n; z) = [ p̂ + z²/(2n) − z·√( p̂(1−p̂)/n + z²/(4n²) ) ] / ( 1 + z²/n )
```

| 战绩 | z=1.00 | z=1.28 | z=1.4548 | z=1.96 |
|---|---|---|---|---|
| 3 胜 0 负 | 0.750 | 0.646 | 0.586 | 0.4385 |
| 6 胜 1 负 | 0.681 | 0.622 | 0.586 | 0.4869 |
| 1 胜 0 负 | 0.500 | 0.378 | 0.321 | 0.2065 |
| 0 胜 1 负 | 0.000 | 0.000 | 0.000 | 0.000 |

否决理由（都是算出来的）：

1. **要翻转「3 局全胜 vs 6 胜 1 负」需要 `z ≥ 1.4548`**（数值二分求得，等价双侧置信 85.4%）。工业界常用取值更低：Reddit 生产代码 `z = 1.2816`（80% 置信），在该取值下 `0.646` 仍排在 `0.622` 之前——**照抄「Reddit 同款参数」等于没改**。
2. **埋没新人**：`z = 1.96` 时 1 胜 0 负 只有 `0.2065`；且 `p̂ = 0` 者的下界对任意 `n` **恒为 0**，0 胜的人大面积并列垫底。与「拉人参与」直接冲突。
3. **目标错配**：下界回答「谁值得被信任在平均之上」，不回答「谁对这个联赛的净贡献更大」。
4. `z` 本身又是自由参数（判据 1 不过）。

**Agresti-Coull 区间下界**（平滑 `p̃ = (w + z²/2)/(n + z²)` 后再算 Wald 下界 `p̃ − z√(p̃(1−p̃)/(n + z²))`，可手算）：翻转 3 局全胜 / 6 胜 1 负 只需 `z ≈ 1.189`（比 Wilson 对小样本更狠，因为平滑把 `6胜1负` 的伪胜率抬得比 `3胜0负` 更高）；`z = 1.96` 时 `0胜1负` 的原始值是 `−0.0390`，必须 clamp 到 `0`，进一步制造并列。**同样否决。**

**乘法式场次加权** `score = p̂ · g(n)`，`g` 严格递增。取 `g(n) = n/(n+4)`（本仓库试过的候选）：

```
12 局 6 胜 6 负 → 0.500 × 12/16 = 0.3750
 7 局 4 胜 3 负 → 0.571 ×  7/11 = 0.3636      → 五成选手排在 57% 前面
```

`p̂ = 0` 的人恒得 0 分，未赢过的新人全部并列垫底。**结论**：乘法加权要么无上界（刷场次），要么有界但把胜率的兑换比交给场数比值。v6 也是乘积形式（命题 3.1 `S = n(90p̂ − 40)`），但乘的是**可以为负的**因子 `90p̂ − 40`，正因为它在 `p̂ = 44.4%` 处为 0、在更低处为负，才不会出现「五成以下刷场次涨分」（命题 3.6）。

**净胜场 `D = w − l`（v3）**：不是「错」，而是目标不同。零参数、`ΣD = 0`（`D = 0` 精确等于联盟中位）、兑换比恒定（多打 2 场换 1 个净胜场），这四条比积分制更硬；但盈亏平衡线在 `50%`，对 `44.4%–50%` 这批人没有出勤激励。**已在 2026-11-17 被积分制替换，替换理由与退回方式见 §6.3、§11。**

**v4 `S = 50w − 30l` 与 v5 `S = 50w − 35l`** 不是「被否的候选」，而是 v6 的前两版：同一族规则、同一套排序键与并列判定，只是比值分别是 `5:3`、`10:7`。它们之所以被换掉，是因为 `p* = 37.5%`、`41.2%` 离内战的真实平均胜率 `50%` 太远，等于用较多的质量换出勤；v6 把天平往质量那边再挪一格（比值 `5:4`、`p* = 44.4%`）。三版都满足上面七条判据，选哪一个属于群规取舍，见 §11。

**Elo / Glicko-2 / TrueSkill**：本仓库每条比赛都带 `player_slot`（天辉 0–4 / 夜魇 128–132），分队信息完整，技术上**可以**上 rating 系统（更进一步是对 10 人做带岭正则的 logistic 回归，即加性分解的 Bradley–Terry 模型，能扣掉队友与对手强度）。但当前**不该上**：

- Glicko-2 官方文档建议每个评分周期内**人均至少 10–15 局**，本快照人均 4.62 局（180 人次 / 39 人）；
- 样本不足时任何 rating 与「个人胜负」类指标排序高度相关，却多出一个说不清的参数（`K` 值或岭正则 `λ`），并引入「更新顺序影响结果」的序贯副作用（判据 3 不过）；
- 随机混排下个人胜负是可得的充分统计量。

**升级触发条件**：联盟累计场数 ≥ 100（约人均 15 局）后，再评估岭回归路线。届时也必须先满足 §6.3 的七条判据，不能又落回「有个可调常数还没公示」。

## 8. 出勤的归属：副榜，不掺进主榜

积分本身已经奖励出勤（命题 3.1：`S = n × (90p̂ − 40)`，`n` 是乘数），定理 2.3 的第二键在同分处再次奖励场数。所以**不需要人为资格线，也不需要往积分里再加出勤权重**。

把出勤按权重塞进主榜的实测污染（`S + μ × 场数`，本快照最活跃者 14 场）：

```
μ =  0 → 前六名里最低胜率 55%
μ =  5 → 55%
μ = 10 → 55%
μ = 20 → 43%
μ = 30 → 43%
```

`μ ≥ 20` 起，胜率 `43%` 的人被顶进前六（v4 的比值更宽，`μ ≥ 10` 就顶进去了；v5 与 v6 都要到 `μ ≥ 20`）。**出勤权重一旦可调，榜单就变成「谁更闲」的排行**，而且 `μ` 又是一个需要人拍的数（判据 1 不过）。注意与 v1/v2 的区别不是「有没有出勤项」，而是「出勤项是否可随手调」。

副榜口径（只比场数，只增不减，没有回归均值的坑）：

```
铁人榜：n_i 降序 → w_i 降序 → 昵称 → account_id
本快照前列：千秋 14 场（6胜8负）、女友太用力害我变直女 11 场（6胜5负）、
            绿箭侠 11 场（5胜6负）、抖音Dota2.Unique_K 10 场（4胜6负）、
            . 9 场（5胜4负）、苏锵锵 9 场（4胜5负）
```

两榜前列几乎不重叠（主榜前三场数 `[7, 7, 3]`、前五场数 `[7, 7, 3, 8, 4]`，铁人榜前三 `[14, 11, 11]`），正好各表扬一批人。**尚未实现**，属于展示层工作。

**赛季冠军资格线**属于**赛事规则**，不属于排名算法：任何资格线都是一个群规常数（例如「出勤 ≥ 联盟最活跃者的 60%」），必须由群内共识确定并写进群规与 `docs/执行标准.md`，不能由算法默认植入，也不能临时调整。当前仓库里没有这条规则，v6 也不需要它。

**明确不建议的三条**：连胜加成（10–20 人的熟人群里「谁在挑对手」全群可见，会引发回避强敌和小号互刷）；缺勤扣分或不活跃衰减（把「想打才打」变成打卡压力，挤出内在动机）；把出勤按权重加进主榜分数（上面的 `μ` 扫描）。

## 9. 实现与测试

代码位置：`site/app.js` 的 `pointsOf()`（积分）、`comparePlayerRanking()`（排序键）、`rankNumbers()`（并列名次）。线上这份就是被测的那份：

```js
const POINTS_PER_WIN = 50;
const POINTS_PER_LOSS = 40;

function pointsOf(player) {
  return player.wins * POINTS_PER_WIN - player.losses * POINTS_PER_LOSS;
}

function comparePlayerRanking(left, right) {
  return (
    pointsOf(right) - pointsOf(left) ||   // 第一键：积分（整数乘减，无除法）
    right.wins - left.wins ||             // 第二键：胜场数（同分时即场数，定理 2.3）
    // 积分与胜场数都相等 ⇒ 负场也相等（命题 2.1）：这两级只决定显示顺序。
    left.name.localeCompare(right.name, "zh-CN") ||
    left.accountId - right.accountId
  );
}

function rankNumbers(players) {    // 名次 = 1 + 压过他的人的人数；并列共用同一数字
  const ranks = [];
  players.forEach((player, index) => {
    const previous = players[index - 1];
    const tied =
      previous !== undefined && previous.wins === player.wins && previous.losses === player.losses;
    ranks.push(tied ? ranks[index - 1] : index + 1);
  });
  return ranks;
}
```

全程整数乘减、不做除法：`S` 相等就进第二键，浮点噪声不会让同一个人在两次刷新之间跳名次（判据 3）。

**表格里排序量本身是可见的。** 现在的表头是：排名、玩家、Account ID、胜、负、总场数、**积分**、**胜率**、**总 K/D/A**。「积分」这一列就是 `pointsOf(player)` 的值，也就是排序用的分数——任何人拿同一张表的「胜」「负」两列代进 `50w − 40l` 就能逐行复算名次，不需要内部数据（这是判据 2 的落地形态）。手机端会隐藏 Account ID、总场数和日期列，**积分、胜、负、胜率、总 K/D/A 始终保留**。

**「总 K/D/A」是参考列，不进排序。** 它等于当前时间范围内该玩家每一局 `kills` / `deaths` / `assists` 的累加（`site/app.js` 的 `calculate()` 累加、`formatKdaTotals()` 格式化），口径与胜负一致：只看能公开识别 Account ID 的位置。缺这三个字段的位置**不计入合计但仍计入场次**，所以那一列的悬停与读屏会写「已汇总 n/m 场」，全缺时显示 `—`，不会造假成 `0/0/0`。把它加进积分需要一个 KDA 权重系数（判据 1 不过），而且 KDA 与胜负本来就不是线性关系，所以这一列只做展示。

**胜率只剩一列，而且改名了。** 原来表里有两列胜率：一列按这名玩家自己的胜负算，另一列定义为「每段队友关系胜率各算一个样本再取平均」，而一场五人队恰好给这个人贡献 4 段队友关系，**按场次加权之后后者精确等于前者**，不加权又只是把同一段关系的输赢重复计入——对排序没有额外信息。内战全部是组队打的，所以「这名玩家的胜率」就是他的联赛胜率 `w/n`，这一列现在就叫**胜率 = 胜场 ÷ 总场数**（v5 一并改名，免得多一个名字让人以为有两种胜率）。同队明细（和每个队友的场次、胜负、胜率）在点 Account ID 弹出的窗口里。

`tests/test_ranking.py` 把 `site/app.js` 里线上那份函数抠出来交给 node 执行（测的就是浏览器里那份代码），当前整套测试 **69 个用例全绿**（其中 `tests/test_ranking.py` 12 个），覆盖：

- **群规钉死**：`POINTS_PER_WIN == 50`、`POINTS_PER_LOSS == 40`；出现积分规则之外的可调常量（`*WEIGHT|*LAMBDA|*PRIOR|*COEFF = 数字`）或比较函数里出现 `/` → 直接失败；
- 公式本身：`6胜1负 260`、`3胜0负 150`、`6胜6负 60`、`1胜3负 −70`；
- 最初那条诉求：`6胜1负(260)` 排在 `3胜0负(150)` 前面；
- **同分比场数**：`11胜5负(350)` 排在 `7胜0负(350)` 前面（这正是 `t = 1` 那一档）；同分且同胜场 ⇒ 顺序与传入顺序无关（判据 3）；
- 盈亏平衡：`4胜5负 = 0 分`（正好 `4/9 ≈ 44.4%`），高于这条线多打涨、低于多打掉；
- 单局杠杆：`w, l ∈ 0..8` 全部 80 种战绩，多赢一局名次只升不降、多输一局只降不升；
- **并列名次**：同战绩共用一个名次、并列不跳号（`1, 2, 2, 4`）、5 人同战绩全部同一名次；
- 1 局全胜进不了前三（给定 7 人对照表，期望顺序 `[1,2,3,4,6,7,5]`）；
- 玩家表的列与渲染跟代码一致（防表头与实现各改各的）：断言表头有积分列 `<th class="col-points">积分</th>`、`renderStats` 里调用 `pointsOf(player)`、只渲染一列胜率且列名叫「胜率」（`renderStats` 里 `makeRateCell(` 只出现一次、表头是 `<th>胜率</th>`）、总 K/D/A 按累加值渲染（`formatKdaTotals(player)` 出现在渲染里）、旧的两列胜率字样不再出现。
- **总 K/D/A 只做累加、不改名次**：`calculate()` 把每一局的杀／死／助分别相加（`1 局 2/1/3` 与 `1 局 4/2/5` ⇒ `6/3/8`），缺字段的场次不进合计但仍计入场次（覆盖数写成「已汇总 1/2 场」），并且刷高 KDA 不会改变名次——排序键仍然只有积分与胜场数。

改标准的流程见 [`docs/执行标准.md`](执行标准.md)：代码 + 测试 + README／本文档／执行标准 同一批提交，改 `app.js` 必须 bump `index.html` 里的 `app.js?v=YYYYMMDD-N`（当前 `app.js?v=20261117-8`、`styles.css?v=20261117-3`）。

## 10. 当前样本量的解读边界

**置换检验**（`H₀`：每场比赛的胜负与场上是谁无关，即选手之间没有技术差异；当前 18 场）：

- 统计量：`χ²/df = Σ_i (w_i − n_i/2)² / (n_i·¼) / (人数 − 1)`
- 重排方式：把每场的 5 个胜场随机重新分配给该场的 10 名选手（保持每场 5 胜 5 负，与命题 1.1 一致），3000 次，随机种子固定 `seed = 20261117`
- 结果：观测值 `0.837`；零分布中位数 `1.015`，2.5%～97.5% 分位 `[0.691, 1.401]`；**置换 p 值 = 0.858**

即**不能拒绝「当前名次差异全部来自运气」**。观测值落在零分布中位数之下，说明当前胜率离散度比纯随机还略小。**这条结论比任何算法选择都重要：现在的名次差主要由样本量决定，不是实力差。** 积分制不对样本量做任何修正（`S = n(90p̂ − 40)` 里的 `p̂` 就是裸样本胜率），所以小样本的人名次本来就会飘：`wa!` 排第 3 是因为他只打了 3 场，`p̂ = 100%` 在 3 场上毫无置信度可言。置换检验与功效分析都只依赖胜负计数，**与 `+50/−40` 这组常数无关**，所以 v5 → v6 之后这两项读数完全没变。

**功效分析**（与各人样本胜率无关，是与 `½` 做单侧检验，`α = 5%`、功效 `80%`）识别一个真实胜率 `p` 的人所需场数：

```
n = (z_{0.95} + z_{0.80})² · p(1−p) / (p − ½)²

真实胜率 55% → 613 场/人    60% → 149 场/人
真实胜率 58% → 236 场/人    65% →  63 场/人
```

**结论**：18 场的榜单承担的是「记功、对账、找乐子」，不承担「评定强弱」。排名标准的职责是**不出现明显荒谬**且**不需要任何人现场做判断**；「多打有回报」由命题 3.1 与定理 3.4 提供，出勤的表扬由 §8 的副榜提供。场均 4.62 场、中位数 3 场意味着大多数人的 `p̂` 只有 2–3 个样本——**别把现在的榜当实力榜看**。

## 11. 必须向群友讲清的取舍

这一版（v6）只动了比值：把输一局又调高 5 分，`a:b` 收到 `5:4`。下面第 1、2 条就是这次调价的代价与收益，说白话，不粉饰。

1. **胜率低于 44.4% 的人，多打会掉分。** 这是 `S = n(90p̂ − 40)` 的直接推论，本快照有 **12 人**（最低 `^^` 1胜7负 = −230 分），比上一版多 1 人：`千秋` 6胜8负、`p̂ = 42.9%` 这次落到线下面。还有 1 人正好踩在线上（`苏锵锵` 4胜5负 = 0 分）。积分的零点只是初始分，不是「中位」（推论 1.2.1）。出勤的表扬走铁人榜（§8），不靠改主榜公式。**不做掩盖。**
2. **这次调价的得与失：为什么选 `5:4`。** 盈亏平衡线抬到 `44.4%`，高于这条线的人从 **28 人变成 26 人**——「拉更多人上场」的激励比上一版更窄。理由是一条闭式事实：内战每场 5v5，联盟按场数加权的真实平均胜率**恰好是 50%**（命题 1.1，本快照核验为 `0.500000`），把盈亏平衡线放在 `44.4%` 就比放在 `41.2%` 更接近这个均值，等于让「掺水的场次」更贵。代价是 `44.4% ~ 50%` 这一段的人多打不再稳赚，出勤奖励的窗口变窄：本快照 `搞心态的神 3胜1负(110 分)` 从第 6 升到第 5，把打满 11 场的 `女友太用力害我变直女 6胜5负(100 分)` 压到第 6；**21 人名次变化**，榜首仍是 `力量护腕`。这是**群规层面的取舍，不是算法缺陷**：想让出勤更占便宜，把 `POINTS_PER_LOSS` 调小一档就回到上一版的 `41.2%`（或任何满足 `p* = b/(a+b)` 的取值），走同一套 PR + 测试 + README／本文档／执行标准流程（§6.1）。
3. **同分时场数多的在前：`11胜5负(350)` 排在 `7胜0负(350)` 前面。** 这是定理 2.3 推论 2 的必然结果，也是「奖励参与」这一目标的直接体现。这一档本季已经撞上两次（§4.3 里 `10 分` 与 `−40 分` 两个分值），场数差都是 9 场；上一版的兑换比是 17 场，所以那一季撞不上。若群里更希望「战绩质量优先」，把两个排序键对调即可（一行改动，同时改本文档与测试，测试会校验）——这属于**赛事规则**层面的选择，不是算法层面。
4. **`6胜1负(260)` 排在 `8胜4负(240)` 前面。** 这是 `a/b = 50/40 = 1.25 < 3/2` 的直接后果（§6.2 的第二条闭式阈值）。上一版 `a/b ≈ 1.4286` 同样小于 `3/2`，这一条方向没变；再上一版 v4 取 `5/3 ≈ 1.667 > 3/2`，那时是 `8胜4负(280)` 压过 `6胜1负(270)`；净胜场（v3）里同样是 `6胜1负` 在前。**阈值是闭式的，不是试出来的**：若群里认为「赢得多」应当压过「赢得少但输得少」，把比值提到 `3/2` 以上就会反转，反之保持 `5:4`。最初那条诉求（7 局 6 胜 1 负 要高于 3 局全胜）在这一版依然成立：`260 > 150`。
5. **并列会共用奖杯。** 战绩完全相同的两人名次相同（命题 2.1），若并列第一就有两个冠军，前三名按名次分配奖杯。本快照有 6 组、21 人并列，最大一组 5 人。同分但战绩不同的人**不**共用名次（§4.3 的 `10 分`、`−40 分` 就是这种：场次多的在前）。这是「不让昵称决定名次」的代价，属于可接受的一侧。
6. **积分不是零和。** 榜上总分 `900 > 0`（命题 1.2，等于 `(a − b)Σw = 10 × 90`），「0 分」不代表中游，只代表盈亏平衡线 `44.4%`；联盟中位是 `50%`。
7. **名次会飘。** 见 §10：置换检验 `p = 0.858`，18 场还分不清实力与运气。
8. **K/D/A 只展示、不进积分。** 表里的「总 K/D/A」是每一局杀／死／助的累加，用来给群友对账和找乐子；任何把它折算进分数的做法都要先由人拍一个权重（判据 1），所以现行标准明确不加。想表扬数据好看的人，走独立的副榜，不动主榜排序。

另外两条不是取舍，是事实：**口径**（哪些场算、谁的分算给谁）比算法更容易引发争议，见 [`docs/执行标准.md`](执行标准.md)；**数据每 15 分钟刷新**，本文 §4 的读数随时会变，重跑 `scripts/rank_stats.py` 即可。

§2.2、§2.3 的排序恒等式在仓库测试之外，用这段 15 行的脚本在 `w, l ∈ 0..20` 的网格上全量验证（输出应为 `440 193160 0`）：

```python
import sys; sys.path.insert(0, "scripts")
from rank_stats import WIN_POINTS as A, LOSS_POINTS as B
recs = [(w, l) for w in range(21) for l in range(21) if w + l]
S = lambda w, l: A * w - B * l
bad = 0
for w1, l1 in recs:
    for w2, l2 in recs:
        dw, dl, dn = w1 - w2, l1 - l2, w1 + l1 - w2 - l2
        d = S(w1, l1) - S(w2, l2)
        bad += (d > 0) != (5 * dw > 4 * dl)     # 定理 2.2(2)：50Δw > 40Δl
        bad += (d > 0) != (9 * dw > 4 * dn)     # 定理 2.2(3)：90Δw > 40Δn
        if d == 0 and (w1, l1) != (w2, l2):      # 同分 ⟺ (Δw,Δl) = (4t,5t)
            bad += (dw % 4) or (dl % 5) or (dw // 4 != dl // 5)
print(len(recs), len(recs) * (len(recs) - 1), bad)
```

实测输出 `440 193160 0`：440 条战绩、193,160 个有序对，两条判别式与「同分 ⟺ `(Δw,Δl) = (4t,5t)`」全部通过。

§4.5 的「追平需要几场」由定理 3.5 直接算，仓库脚本里没有这一项，用这段复核前 8 名：

```python
import sys; sys.path.insert(0, "scripts")
from rank_stats import load, rank_points, points_of, name_of
players, *_ = load()
order = rank_points(players)
for i in range(8):
    a = order[i]; w = int(players[a]["wins"]); n = int(players[a]["games"])
    gain = 90 * (w / n) - 40
    gap = points_of(players[order[i - 1]]) - points_of(players[a]) if i else 0
    print(f"{name_of(players, a):20s} {points_of(players[a]):4d} " +
          (f"{gap / gain:.1f} 场" if gain > 0 else "按自己的胜率追不上"))
```

两处不在脚本里、需要手算或用 node：Wilson / Agresti-Coull 的 `z` 翻转临界值（§7 的 `1.4548`、`1.189`，数值二分求根，正态分位可用 `math.erf` 自行实现，本仓库未装 `scipy`）；以及 §5.4 的「交叉相乘恒等于 1」，那是恒等式，展开即得。
