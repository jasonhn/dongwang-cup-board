# 内战光荣榜排名标准（现行 v3：净胜场）

本文给出榜单排序标准的**完整定义、可证明的性质、以及被否方案的反例**。文中所有数值都是在仓库里的 `site/data/league.json` 快照（**2026-11-17：18 场、39 名选手、180 人次出场、场数中位数 3**）上算出来的，复现命令见附录 A。

**现行标准是零参数的**：排序只用每个人的胜场与负场做整数加减，不含任何需要人拍板的常数、权重或门槛。历史上用过的 v1/v2（往 50% 收缩的"修正胜率"）需要人为指定先验强度 `k`，已被废弃，废弃理由的数学依据在 §4。

分工：**§1–§5 是标准本身的性质，与打多少场无关，长期有效**；§2.4、§9 的表是**当前快照的读数**，每 15 分钟采集一次数据就会变，重跑 `scripts/rank_stats.py` 即可刷新，不必怀疑推导。**一场比赛是否计入、谁的胜负算给谁**属于统计口径，见 [`docs/执行标准.md`](执行标准.md)，与本文无关。外部文献来源单独标注，见 §6 附注。

## 1. 记号与前提

| 记号 | 含义 |
|---|---|
| `i` | 一名选手（`account_id` 唯一确定） |
| `w_i` | 在当前时间范围内该选手被统计到的**胜场**数 |
| `l_i` | 负场数 |
| `n_i = w_i + l_i` | 总场数（`n_i ≥ 1`，`n_i = 0` 的人不出现在表里） |
| `p̂_i = w_i / n_i` | 样本胜率，也就是表格里显示的那个数 |
| `D_i = w_i − l_i = 2w_i − n_i` | **净胜场**，现行排序量 |
| `≻` | 榜单的排序关系（严格全序，由 §2 定义） |

**前提 P1**：一场比赛被统计到的天辉、夜魇人数相同（内战 5v5，10 个位置全部非匿名）。口径体检会逐场检查这个前提，见 §8。

**命题 1（联盟平均胜率恒等于 ½，且净胜场总和恒等于 0）** 若 P1 成立，则 `Σ_i w_i = Σ_i l_i`，于是按场数加权的联盟平均胜率

```
Σ w_i / Σ n_i = ½        且        Σ_i D_i = 0
```

**证明** 每场比赛恰好贡献 `m` 个胜场与 `m` 个负场（`m = 5`），对全体求和即得 `Σ w_i = m·(场数) = Σ l_i`；两式相减即 `Σ D_i = 0`。∎

本快照核验：`Σ 胜 = Σ 负 = 90`，加权平均胜率 = `0.500000`，且不存在两队人数不等的场次。

这条结论的实际用处：`D` 的零点不需要估计。任何"往联盟均值收缩"的评分都要先有一个收缩目标，而这里目标精确是 `½`（没有估计误差）；净胜场则**根本不需要同一个常数**——`Σ D = 0` 说明 `D = 0` 就是联盟中位水平，它是从守恒式推出来的，不是谁设定的。

## 2. 现行标准 v3

### 2.1 定义

排序键是 `(D_i, w_i)` 的字典序降序：

```
D_i = w_i − l_i = 2w_i − n_i

i ≻ j  ⟺  D_i > D_j
        或（D_i = D_j 且 w_i > w_j）
```

`D` 与 `w` 都相等时，两人的战绩完全相同（见命题 2.3），此时按昵称（`zh-CN` 字典序）再 `account_id` 升序**只决定表内的显示顺序**，**名次相同**（并列，见 §2.3）。

排名表里显示的是真实胜率 `p̂`，排序用的是 `D`。两者都由 `w`、`l` 两列直接算出，页面上没有任何隐藏状态。

### 2.2 排序关系是全序

`≻` 由 `(D, w)` 在 `ℤ × ℕ` 上的字典序给出，是严格全序：任意两人必可比较且先后唯一，传递性成立。**排名不依赖比赛录入顺序、不依赖刷新次数、不依赖历史名次**——同一份 `w/l` 输入永远得到同一份榜单。带先验的评分同样满足这条；Elo/Glicko 这类逐局更新的 rating 不满足（更新顺序会影响结果，见 §6）。

### 2.3 并列名次

**命题 2.3（并列的充要条件）** `D_i = D_j` 且 `w_i = w_j` ⟺ `w_i = w_j` 且 `l_i = l_j`。

**证明** 由 `l = 2w − D`：`D`、`w` 相等则 `l` 相等；反向显然。∎

也就是说：第二排序键之后**不存在"还能区分但不该区分"的情形**。标准无法区分两个人时，就给他们同一个名次，而不是靠昵称字母序决定谁是冠军。名次按"标准体育并列"（1, 2, 2, 4）编号：

```
rank(i) = 1 + |{ j : j ≻ i }|
```

实现见 §8。**这是把"排序"与"定名次"分开：显示顺序需要确定性，名次不需要。**

## 3. 标准的性质

**命题 3.1（场数与质量是乘积关系）**

```
D_i = n_i · (2p̂_i − 1)
```

**证明** `D = 2w − n = n(2w/n − 1) = n(2p̂ − 1)`。∎

解读：`2p̂ − 1` 是"超出五成的部分"的两倍，净胜场 = 场数 × 超额胜率。**场数和质量都是乘数**，缺一个都得 0：

- `p̂ = ½` ⇒ `D = 0`，打满整个赛季也是 0：**刷场次对五成选手零收益**（本快照胜率正好五成的 8 人，`D` 全是 0）；
- `n = 1` ⇒ `D ≤ 1`：只打一场的人天花板很低；
- 一个 60% 的人每 5 场净增 1 个净胜场，一个 70% 的人每 10 场净增 4 个。**打得多确实有回报，且回报是线性的、不会衰减**。

**定理 3.2（跨场数比较的闭式判据）**

```
i ≻ j（第一键决胜） ⟺  2(w_i − w_j) > n_i − n_j
```

**证明** `D_i > D_j ⟺ 2w_i − n_i > 2w_j − n_j`，移项即得。∎

这条是整个标准最好用的表述：**场数差要用胜场差来抵，兑换比恒定为"多打 2 场换 1 个净胜场"，不随场数变化**。代入用户最初那条诉求：

| 对比 | `2Δw` | `Δn` | 判据 | 结果 |
|---|---|---|---|---|
| 6胜1负(7场) vs 3胜0负(3场) | 6 | 4 | 6 > 4 | 6胜1负 在前 ✅ |
| 12胜2负(14场) vs 5胜0负(5场) | 14 | 9 | 14 > 9 | 12胜2负 在前 ✅ |
| 25胜5负(30场) vs 10胜0负(10场) | 30 | 20 | 30 > 20 | 25胜5负 在前 ✅ |
| 30胜6负(36场) vs 15胜0负(15场) | 30 | 21 | 30 > 21 | 30胜6负 在前 ✅ |

**推论 3.2.1（同胜率比场数）** 若 `p̂_i = p̂_j = p`，则 `D_i > D_j ⟺ n_i > n_j`（当 `p > ½`），即**同样水平的人，打得多的在前**。

**推论 3.2.2（不存在"反超所需的参数"）** v2 里"场多的人要反超场少的人"需要一个人拍板先验强度 `k`，且所需 `k` 随场数线性上涨（命题 4.1）。这里判据 `2Δw > Δn` 里**没有自由参数**，对任何场数尺度都成立——这就是"统一"的准确含义。

**定理 3.3（每局的得失对所有人恒等）** 战绩 `(w, l)` 再打一局：胜则 `D → D + 1`，负则 `D → D − 1`。**与当前场数、当前胜率、当前名次无关。** 若本人真实胜率为 `p`（中性假设 `p = ½`），则期望变化

```
E[ΔD] = p·(+1) + (1 − p)·(−1) = 2p − 1
```

`E[ΔD]` 只跟真实胜率有关：胜率高于五成的人多打**期望涨**，低于五成的人多打**期望跌**，正好五成的人不变。对照 v1/v2 的对应结论（定理 4.4）：那里的期望变化符号由"样本胜率与 ½ 的相对大小"决定，**高于均值的人多打一局期望要掉分**，会催生"保住名次就别打"。v3 没有这个坑：`p > ½` 的人多打永远是正期望。

**定理 3.4（单调性）** 对任意战绩，胜场 +1 使 `D` +1（名次不降），负场 +1 使 `D` −1（名次不升）。这条在 `w, l ∈ 0..8` 的全部 80 种战绩组成的网格上逐点验证（`tests/test_ranking.py`）。

注意与定理 3.3 的区别：**单局结果**永远 ±1，**期望**取决于本人胜率。所以"多打会不会涨名次"这个问题在 v3 里有确定答案：只要你的真实胜率高于五成，多打就涨。低于五成时多打会掉名次——这是标准的取舍，不是 bug，见 §10。

**命题 3.5（同 `D` 时比胜场数 = 比场数）** `D` 相等时 `n = 2w − D`，故 `w` 更大 ⟺ `n` 更大。第二排序键就是"打得多者在前"，与命题 2.3 一起构成完整的并列规则。

**命题 3.6（与体育积分榜同构）** `D = 2w − n` 等价于"每胜积 2 分、每负积 0 分"的积分，而第二键比胜场数，与足球小组赛"积分 → 净胜球 → 进球数"的排序结构相同。这是类比，不附出处；它的作用是说这套口径**不是自创的**，任何群友拿一张积分榜都能对上。

## 4. 为什么废弃需要常数的 v1 / v2

v1（2026-11-17 之前线上）与 v2（同日短暂上线）都是往 ½ 收缩的"修正胜率"：

```
score_k(w, n) = (w + k/2) / (n + k)
v1: k = 2   （Beta(1,1) 均匀先验的后验均值，即 Laplace 平滑）
v2: k = 6   （Beta(3,3)）
```

**命题 4.1（收缩即凸组合）** 记 `λ(n) = n/(n + k)`，则

```
score_k(w, n) = λ(n)·p̂ + (1 − λ(n))·½
```

**证明** `w = n·p̂`，代入 `(n·p̂ + k/2)/(n + k) = [n·p̂ + k·½]/(n + k)`，拆两项。∎

`λ` 是"样本可信度"，`k` 是"半信半疑所需的场数"。**这里出现了第一个自由参数**：`k` 取 2、6 还是 10，没有任何外部依据能定，只能由人拍板。下面的命题说明它还有三个可测量的坏处。

**命题 4.2（反超所需的 `k` 随场数线性上涨）** 设 `(w₁,n₁)`、`(w₂,n₂)`，`n₂ > n₁`。则

```
score_k(w₂,n₂) ≥ score_k(w₁,n₁)  ⟺  k ≥ k* = 2(w₂n₁ − w₁n₂) / ( 2(w₁ − w₂) + (n₂ − n₁) )
```

**证明** 两端同乘正数 `(n₁+k)(n₂+k)`，`k²/2` 项消掉：

```
w₁n₂ − w₂n₁ + k[ (w₁ − w₂) + (n₂ − n₁)/2 ] ≤ 0
```

记分母 `D₀ = (w₁ − w₂) + (n₂ − n₁)/2`。在 `p̂₂ ≤ p̂₁`（场多的人胜率不占优）时 `D₀ > 0`，移项即得闭式解。∎

| 想让谁排前面 | 临界 k\* |
|---|---|
| 6 胜 1 负 > 3 局全胜 | **3.0** |
| 12 胜 2 负 > 5 局全胜 | 4.0 |
| 25 胜 5 负 > 10 局全胜 | 10.0 |
| 30 胜 6 负 > 15 局全胜 | 20.0 |

**推论 4.2.1（一次齐次）** `(w,n)` 同乘 `c` 则 `k*` 乘 `c`（实测 1×/2×/4×/10× → 3/6/12/30）。**结论：不存在一个"配好之后长期有效"的 `k`。** 赛季每多打十几场就得重新拍一次参数，而每次拍板的依据都不同——这正是"主观干预"的具体形态。v3 的判据（定理 3.2）在任何场数下是同一条不等式。

**命题 4.3（`k` 越大区分度越平）** 场数相同、胜率相差 `Δp` 的两人，分数差 `= n·Δp/(n + k)`。20 场 75% 与 60% 的分差：`k=2` 时 0.1364，`k=6` 时 0.1154，`k=12` 时 0.0938。**修小样本问题要靠调大 `k`，而调大 `k` 会磨平老手之间的差距**——两难，且取舍点由人定。

**定理 4.4（收缩式对出勤非单调）** 战绩 `(w,n)` 再打一局，`p = ½` 时

```
E[Δ score_k] = (n/2 − w) / ( (n + k)(n + k + 1) )
```

符号完全由 `p̂` 与 ½ 的相对大小决定：`p̂ > ½` 时多打一局期望**掉分**（3 局全胜在 `k=6` 下期望 −0.0167），`p̂ < ½` 时期望**涨分**，`p̂ = ½` 时恒为 0（**出勤对分数零收益**）。

**证明** `E[score'] = ½·(w+1+k/2)/(n+k+1) + ½·(w+k/2)/(n+k+1) = (w+k/2+½)/(n+k+1)`，减去 `(w+k/2)/(n+k)`，通分即得。∎

这条与 v3 的对照很关键：v1/v2 会让"目前排得最好的人"面临**多打要掉分**的局面（回归均值），而 v3 里每个真实胜率高于五成的人多打都是正期望。**激励参与这件事，收缩式在数学上做不到，净胜场做得到。**

**定理 4.5（加法先验的一条不可能性）** 对一切 `k > 0`，

```
(1 + k/2)/(1 + k) > (2 + k/2)/(3 + k)
```

因为交叉相乘之差**恒等于 1**：`(1+k/2)(3+k) − (2+k/2)(1+k) = 3 + 2.5k + 0.5k² − 2 − 2.5k − 0.5k² = 1 > 0`。

**推论** 无论 `k` 多大，`1 胜 0 负` 永远排在 `2 胜 1 负` 前面——v2 没能修掉这一条。**v3 用第二排序键把它修掉了**：两者 `D` 都是 1，胜场数 `2 > 1`，所以 `2 胜 1 负` 在前（本快照里 2胜1负 并列第 10、1胜0负 并列第 14）。这是一个**不需要参数就能解决**的问题，只是 v1/v2 的函数形式把信息丢掉了。

**废弃 v2 的完整理由（三条，都是可测的）**

1. `k` 无统一取值，且随联盟规模漂移（命题 4.2 推论 4.2.1）；
2. `k` 越大老手区分度越平（命题 4.3），取舍点需人定；
3. 高于五成的人多打期望掉分（定理 4.4），与"鼓励参与"的目标在数学上冲突；另有定理 4.5 这一条修不掉的不可能性。

v3 四条全部避免，且**不含任何可调系数**。`tests/test_ranking.py` 里有一条守卫测试：一旦 `site/app.js` 里重新出现可调参数常量、或比较函数里出现除法，测试直接失败。

## 5. 什么叫"统一且客观"（本仓库采用的判据）

| # | 判据 | v3 | v1/v2 | Wilson 下界 | `p̂ × 场次系数` |
|---|---|---|---|---|---|
| 1 | 无自由参数（不需人拍板任何常数/权重/门槛） | ✅ | ❌ `k` | ❌ `z` | ❌ 系数形式 |
| 2 | 排名可由表内两列自行复算 | ✅ | ✅ | ✅ | ✅ |
| 3 | 不依赖输入顺序与历史状态 | ✅ | ✅ | ✅ | ✅ |
| 4 | 每局的得失对所有人恒等（不因当前名次高低而变） | ✅ ±1 | ❌ 定理 4.4 | ❌ 下界随 `n` 变化 | ❌ 边际随 `n` 变化 |

| 7 | 兑换比恒定，不随场数漂移 | ✅ 2 场换 1 净胜场 | ❌ `k*` 线性上涨 | ❌ | ❌ |

第 1、4、7 条是这次改动真正的分水岭：**只要标准里有一个可调常数，榜上每个名次都隐含"某人做过一个选择"**。第 2、3 条早就满足，不是本次的问题。

## 6. 被否掉的候选方案

**Wilson 得分下界**（App Store / Reddit 评分排序那一路）

```
LCL(w, n; z) = [ p̂ + z²/(2n) − z·√( p̂(1−p̂)/n + z²/(4n²) ) ] / ( 1 + z²/n )
```

| 战绩 | z=1.00 | z=1.28 | z=1.4548 | z=1.96 |
|---|---|---|---|---|
| 3 胜 0 负 | 0.750 | 0.646 | 0.586 | 0.4385 |
| 6 胜 1 负 | 0.681 | 0.622 | 0.586 | 0.4869 |
| 1 胜 0 负 | 0.500 | 0.378 | 0.321 | 0.2065 |
| 0 胜 1 负 | 0.000 | 0.000 | 0.000 | 0.000 |

否决理由（都是算出来的）：

1. **要翻转"3 局全胜 vs 6 胜 1 负"需要 `z ≥ 1.4548`**（数值二分求得，等价双侧置信 85.4%）。工业界常用取值更低：Reddit 生产代码 `z = 1.2816`（80% 置信），在该取值下 0.646 仍排在 0.622 之前——**照抄"Reddit 同款参数"等于没改**。
2. **埋没新人**：`z = 1.96` 时 1 胜 0 负 只有 0.2065；且 `p̂ = 0` 者的下界对任意 `n` **恒为 0**，0 胜的人大面积并列垫底。与"拉人参与"直接冲突。
3. **目标错配**：下界回答"谁值得被信任在平均之上"，不回答"谁对联赛净贡献更大"。
4. `z` 本身又是自由参数（判据 1 不过）。

**Agresti-Coull 区间下界**（"add-2"平滑后算 Wald 区间，可手算）：翻转 3 局全胜/6 胜 1 负 只需 `z ≈ 1.189`（比 Wilson 对小样本更狠）；`z = 1.96` 时 0 胜 1 负的原始值是 `−0.0390`，必须 clamp 到 0，进一步制造并列。**同样否决。**

**乘法式场次加权** `score = p̂ · g(n)`，`g` 严格递增。取 `g(n) = n/(n+4)`（本仓库试过的候选）：

```
12 局 6 胜 6 负 → 0.500 × 12/16 = 0.3750
 7 局 4 胜 3 负 → 0.571 ×  7/11 = 0.3636      → 五成选手排在 57% 前面
```

`p̂ = 0` 的人恒得 0 分，未赢过的新人全部并列垫底。**结论**：乘法加权要么无上界（刷场次），要么有界但把胜率的兑换比交给场数比值。**v3 也是乘积形式（命题 3.1），但乘的是超额胜率 `2p̂ − 1`**——正因为这个因子可以为负、且在 `p̂ = ½` 处为 0，才不会出现"五成刷场次涨分"。

**Elo / Glicko-2 / TrueSkill**：本仓库每条比赛都带 `player_slot`（天辉 0–4 / 夜魇 128–132），分队信息完整，技术上**可以**上 rating 系统（更进一步是对 10 人做带岭正则的 logistic 回归，即加性分解的 Bradley–Terry 模型，能扣掉队友与对手强度）。但当前**不该上**：

- Glicko-2 官方文档建议每个评分周期内**人均至少 10–15 局**，本快照人均 4.62 局（180 人次 / 39 人）；
- 样本不足时任何 rating 与"个人胜负"类指标排序高度相关，却多出一个说不清的参数（`K` 值或岭正则 `λ`），并引入"更新顺序影响结果"的序贯副作用（判据 3 不过）；
- 随机混排下个人胜负是可得的充分统计量。

**升级触发条件**：联盟累计场数 ≥ 100（约人均 15 局）后，再评估岭回归路线。届时也必须先满足 §5 的七条判据，不能又落回"有个可调常数"。

**§6 附注（出处与核实状态）** 本文里除下列三条外，所有数值都是在仓库快照上自算、可复现的（附录 A）：

- Reddit 排序实现与 `z = 1.281551565545 # 80% confidence`：来自开源仓库 `reddit/reddit` 的 `r2/r2/lib/db/_sorts.pyx`（本次调研抓取原文核实）。
- Glicko-2 的"人均 10–15 局"建议：来自 `glicko.net/glicko/glicko2.pdf`（抓取原文核实）。
- OpenDota 英雄榜 `score = G × (G/(L+1)) × MMR` 与 `games >= 10` 门槛：来自 `odota/core` 的 `sql/ranking.sql`（抓取核实）。它是"场次权重 + 硬门槛"的成熟先例，但 `G²` 无上界，会鼓励刷场次，故未采用。

## 7. 出勤的归属：副榜，不掺进主榜

净胜场本身已经在奖励出勤（命题 3.1：`D = n × 超额胜率`），所以**不需要人为资格线**。剩下的问题是"全勤但胜率不足五成的人怎么被表扬"——答案是**另开一条只比场数的副榜**，不是往主榜分数里加权重。

把出勤按权重加进主榜的实测污染（`score_v2 + λ × (场数 / 最活跃者场数)`，本快照最活跃者 14 场）：

| λ | 0.00 | 0.02 | 0.04 | 0.06 | 0.10 |
|---|---|---|---|---|---|
| 前六名里最低胜率 | 62% | 62% | 62% | **55%** | 55% |

`λ = 0.06` 起，低于五成的人被顶进前六，而 1 胜 0 负 的反被挤掉。**出勤权重一旦可调，榜单就变成"谁更闲"的排行**——而且 `λ` 又是一个需要人拍的数（判据 1 不过）。

副榜口径（只比场数，只增不减，没有回归均值的坑）：

```
铁人榜：n_i 降序 → w_i 降序 → 昵称 → account_id
本快照前列：千秋 14 场（6胜8负）、女友太用力害我变直女 11 场、绿箭侠 11 场、
            抖音Dota2.Unique_K 10 场、. 9 场、卖鱼！ 9 场
```

两榜前列几乎不重叠（主榜前三 7、7、3 场；铁人榜前三 14、11、11 场），正好各表扬一批人。**尚未实现**，属于展示层工作。

**赛季冠军资格线**属于**赛事规则**，不属于排名算法：任何资格线都是一个群规常数（例如"出勤 ≥ 联盟最活跃者的 60%"），必须由群内共识确定并写进群规与 `docs/执行标准.md`，不能由算法默认植入，也不能临时调整。当前仓库里没有这条规则，v3 也不需要它。

**明确不建议的三条**：连胜加成（10–20 人的熟人群里"谁在挑对手"全群可见，会引发回避强敌和小号互刷）；缺勤扣分或不活跃衰减（把"想打才打"变成打卡压力，挤出内在动机）；把出勤按权重加进主榜分数（上面的 λ 扫描）。

## 8. 实现与测试

代码位置：`site/app.js` 的 `comparePlayerRanking()`（排序键）与 `rankNumbers()`（并列名次）。

```js
function comparePlayerRanking(left, right) {
  const netLeft = left.wins - left.losses;
  const netRight = right.wins - right.losses;
  return (
    netRight - netLeft ||          // 第一键：净胜场（整数相减，无除法、无常数）
    right.wins - left.wins ||      // 第二键：胜场数
    // 净胜场与胜场数都相等时，负场与总场数也相等（命题 2.3）：
    // 这两级只决定显示顺序，不影响名次。
    left.name.localeCompare(right.name, "zh-CN") ||
    left.accountId - right.accountId
  );
}

function rankNumbers(players) {    // 名次 = 1 + 压过他的人的人数；并列共用同一数字
  const ranks = [];
  players.forEach((player, index) => {
    const previous = players[index - 1];
    const tied =
      previous !== undefined && previous.wins === player.wins && previous.losses === player.losses;
    ranks.push(tied ? ranks[index - 1] : index + 1);
  });
  return ranks;
}
```

只用整数相减，不做除法：`D` 相等就进入第二键，浮点噪声不会让同一个人在两次刷新之间跳名次。

`tests/test_ranking.py` 把 `site/app.js` 里线上那份函数抠出来交给 node 执行（测的就是浏览器里那份代码），覆盖：

- **零参数守卫**：`app.js` 里出现 `RANKING_PRIOR_*` / `RANKING_WEIGHT` 之类可调常量，或比较函数体里出现 `/` → 失败；
- 最初那条诉求：6 胜 1 负 排在 3 胜 0 负 前面；
- 1 局全胜进不了前三（给定 7 人对照表，期望顺序 `[1,2,3,4,6,5,7]`）；
- 同 `D` 比胜场数，且同战绩的顺序与传入顺序无关（判据 3）；
- **并列名次**：同战绩共用一个名次、并列不跳号、5 人同战绩全部同一名次；
- 单调性网格：`w,l ∈ 0..8` 全部 80 种战绩，多赢一局名次只升不降、多输一局只降不升；
- `site/index.html` 上写给群友看的口径说明与代码一致（防说明与实现各改各的）。

改标准的流程见 [`docs/执行标准.md`](执行标准.md)：代码 + 测试 + 页面文案 + 本文档同一批提交，改 `app.js` 必须 bump `index.html` 里的 `app.js?v=YYYYMMDD-N`。

## 9. 当前样本量的解读边界

**置换检验**（`H₀`：每场比赛的胜负与场上是谁无关，即选手之间没有技术差异；当前 18 场）：

- 统计量：`χ²/df = Σ_i (w_i − n_i/2)² / (n_i·¼) / (人数 − 1)`
- 重排方式：把每场的 5 个胜场随机重新分配给该场的 10 名选手（保持每场 5 胜 5 负，与命题 1 一致），3000 次，随机种子固定 `seed = 20261117`
- 结果：观测值 `0.837`；零分布中位数 `1.015`，2.5%～97.5% 分位 `[0.691, 1.401]`；**置换 p 值 = 0.858**

即**不能拒绝"当前名次差异全部来自运气"**。观测值落在零分布中位数之下，说明当前胜率离散度比纯随机还略小。**这条结论比任何算法选择都重要：现在的名次差主要由样本量决定，不是实力差。** 净胜场只是把它如实显示出来（`D = n × 超额胜率` 里没有对样本量做修正，所以小样本的人名次本来就会飘）。

**功效分析**（与 ½ 做单侧检验，`α = 5%`、功效 `80%`）识别一个真实胜率 `p` 的人所需场数：

```
n = (z_{0.95} + z_{0.80})² · p(1−p) / (p − ½)²
```

| 真实胜率 | 55% | 58% | 60% | 65% |
|---|---|---|---|---|
| 需要场数/人 | 613 | 236 | **149** | 63 |

**结论**：18 场的榜单承担的是"记功、对账、找乐子"，不承担"评定强弱"。排名标准的职责是**不出现明显荒谬**且**不需要任何人做判断**；"多打有回报"由命题 3.1 的乘积关系与 §7 的副榜提供。

## 10. 必须向群友讲清的三条取舍

1. **胜率低于五成的人，多打会掉名次。** 这是 `D = n(2p̂ − 1)` 的直接推论，也是"净胜场"这个词的本意：一个人对联盟的净贡献。出勤的表扬走铁人榜（§7），不靠改主榜公式。**不做掩盖**。
2. **6 胜 1 负（净 5）排在 8 胜 4 负（净 4）前面。** 即质量优先于纯胜场数；若群友更希望"胜场数优先"，把两个排序键对调即可（一行改动，同时改页面文案，测试会校验）。这个取舍点是**赛事规则**层面的，不是算法层面。
3. **并列会共用奖杯。** 战绩完全相同的两人名次相同，若并列第一就有两个冠军，前三名按名次分配奖杯。这是"不让昵称决定名次"的代价，属于可接受的一侧。

另外两条不是取舍，是事实：名次飘（§9）；口径（哪些场算、谁的分算给谁）比算法更容易引发争议，见 [`docs/执行标准.md`](执行标准.md)。
